# mental v1.2 — design

Date: 2026-10-21 · Branch: `v1.2` · Builds on: the v1 and v1.1 specs (everything there still holds
unless this file changes it).

## What changes and why

v1.1 forgets everything when the tab closes, so you can measure one run but never see yourself
improve. v1.2 makes the app **remember you**:

1. **Players.** Pick or create a player name on this computer. Everything you play is saved under it.
2. **Saved rounds.** Every finished test, and every Practice session you quit, is stored in a local
   SQLite file with all its attempts.
3. **Personal best** for the 2-minute test, shown on its results.
4. **My stats**: your test history and how you do per topic, over everything you have played.
5. **Leaderboard**: best test score per player on this computer.
6. **Free Play is renamed Practice** and gets a **Quit** button that ends the session with a summary
   (per-question times included; Practice has always timed each question without showing it).
7. The server **re-checks every saved answer** itself instead of trusting the browser.
8. Pages are served with `Cache-Control: no-cache`, so a normal reload always picks up a new version.

## Accounts, leaderboards and safety: the thinking

There is no server anyone else can reach yet: the app runs on `127.0.0.1`. So v1.2 does **not**
build logins. It builds the part of accounts that everything else hangs off, and leaves the
password part for when the app goes online.

| Stage | What a "user" is | Leaderboard |
|---|---|---|
| **v1.2 (this)** | a **player**: a name on this computer, no password | best test score per player on this computer |
| later, with deployment | an **account**: the same player row plus a password and a login session | the same query, over everyone |

Why no password now: anyone at this keyboard can already open the database file, so a password
would protect nothing and only add a login screen. Because every saved row already belongs to a
player id, adding accounts later is: a password-hash column on `players`, a login that sets a
session cookie, and the API taking the player from the cookie instead of the request body. No data
moves.

When accounts arrive (not now), the plan is: passwords hashed with the standard library's
`hashlib.scrypt` and a per-user random salt (no new dependency); a random session token in an
`HttpOnly`, `SameSite=Lax` cookie stored in a `logins` table; rate-limited login attempts; and the
test timed by the server (it records when it handed out the questions) so a score can't be faked
by editing the browser's clock.

**SQL injection.** The 5-digit answer box does not protect the server: it only exists in the
browser, and anyone can send any JSON straight to `/api/...` with `curl`. What protects the
database is how the queries are written:

- Every SQL statement is a fixed string with `?` placeholders; values are always passed separately
  (`conn.execute("... WHERE id = ?", (player_id,))`). No f-string, `%` or `+` ever builds SQL.
  A test saves a player named `Robert'); DROP TABLE rounds;--` and checks it comes back unchanged.
- Every request body is checked by Pydantic before it reaches the database: player names are
  1–16 characters of letters, digits, spaces, `_`, `-` and `.`; a round has at most 1000 attempts;
  every number has a range.

**Script injection (XSS)** is the bigger risk once names are shown to other people: a player named
`<img src=x onerror=alert(1)>` must show up as that text, never run. Rule: **anything a person typed
is put on the page with `textContent`, never `innerHTML`**. The browser check creates such a player
and checks it renders as plain text.

**Cheating.** The browser decides nothing that counts. When a round is saved, the server rebuilds
each question from its id (`<category>-<level>-<seed>`), checks the text matches, and works out
`correct` and the score from what was typed. A round may not repeat a question. The page is still
sent each answer with its question, so a scripted fake run is possible on this computer (where the
database is editable anyway); when the app goes online the server keeps the answers and times the
test itself.

## Players

- On load the page asks the server for the player list. It remembers the last player in the
  browser (`localStorage`). If that player still exists, go straight to home.
- Otherwise the **who's playing?** screen shows: one choice per existing player, then a name box
  with **Add**. A new name must follow the name rules above and must not already exist (ignoring
  case): otherwise a message says why and you stay on the screen.
- Home shows `playing as <name>` and a **Switch player** choice that opens the same screen.
- If the server can't be reached, the screen says so and shows a **Retry** choice.

## Home

Choices, top to bottom: **Practice**, **Test Yourself · 2 min**, **My stats**, **Leaderboard**,
**Switch player**. Arrow keys and mouse work exactly as in v1.1. Coming back from My stats,
Leaderboard or Switch player (Esc or Back) highlights the choice you came from.

## Practice (was Free Play)

Everything from v1.1 Free Play, renamed (the settings line reads `practice · …`, the attempt record
`mode` is `"practice"`), plus:

- A **Quit** button next to Enter and Give up. **Esc** does the same.
- Quit ends the session. The question on screen when you quit is not recorded (as in the test).
  If nothing was answered or given up, it goes straight home. Otherwise it shows the **summary**:
  questions done, solved first try, gave up, average time, a per-topic table, and the slowest
  questions with their methods (the same layout as the test results), then saves the session.
- On the summary: Enter practises again with the same settings (after a 1-second guard), Esc goes home.
- Closing or reloading the tab mid-practice still saves the questions you finished (best effort,
  `navigator.sendBeacon`; browsers cap beacons at about 64KB, so roughly the first 200 questions
  of a very long session).
- If saving fails, the message says so and Enter or **Retry** tries again. Leaving with Esc instead
  drops that session. If the server saved it but the reply was lost, a retry saves it a second
  time (rare; there is no way to tell the two apart without a round id from the server).
- Each question is timed from when it appears until it is solved or given up. The time is not shown
  while playing; it appears in the summary and is saved.

## Test Yourself

As v1.1. On saving, the results add a best line:
- first test for this player → `first test · best <score>`
- beat the best → `new best! (was <old>)`
- otherwise → `best <best>`

Esc during a test still abandons it: nothing is saved and it doesn't count.

## My stats

For the current player, over everything saved:
- **Tests**: how many, best score, and the last 10 scores with their dates.
- **By topic** (both modes): questions, solved, first-try %, average time.
- Esc (or a **Back** choice) goes home.

## Leaderboard

Top 10 players on this computer by best test score (ties: alphabetical). Players with no test are
left out. Your row is highlighted. Esc or Back goes home.

## Storage

- One SQLite file. Location: `$MENTAL_DB` if set, else `~/.mental/mental.db` (created on first use).
  Python's built-in `sqlite3`: no new dependency.
- Tables: `players`, `rounds` (one finished test or practice session), `attempts` (one row per
  attempt record). `PRAGMA user_version` holds the schema version (1) so later versions can migrate.
- Times are stored as UTC ISO strings, set by the server.

## API

| Route | Body / params | Returns |
|---|---|---|
| `GET /api/players` | — | `[{id, name}]` in name order |
| `POST /api/players` | `{name}` | `{id, name}`; 409 name taken; 422 bad name |
| `POST /api/rounds` | `{player_id, mode, attempts}` | `{summary, best}` (`best` is `null` for practice); 404 unknown player; 400 an attempt doesn't match its question |
| `GET /api/players/{id}/stats` | — | `{tests: {count, best, recent: [{score, at}]}, by_category}`; 404 unknown player |
| `GET /api/leaderboard` | — | `[{id, name, best}]` (the id lets the page highlight your row) |

`POST /api/summary` is removed: saving a round returns its summary.

## Not in v1.2

Passwords, logins and online accounts; deleting players or history; per-trick weakness lists and
practice that targets weak spots (v1.3); more test lengths; visual redesign; deployment.
