# mental v1.3 — design

Date: 2026-10-21 · Branch: `v1.3` · Builds on: the v1, v1.1 and v1.2 specs (everything there still
holds unless this file changes it).

## What changes and why

v1.2's players are names typed on this computer with no proof of who anyone is: anyone at the
keyboard can play as anyone. The app is also heading for the public web (after v1.4's design
overhaul). v1.3 replaces name players with **Sign in with Google**, keeps **guest play** for people
who don't sign in, and makes the sign-in and sessions ready for the web, without deploying yet.

- Signed in: everything is saved, you get a best score, My stats, and a place on the leaderboard.
- Guest: Practice and Test work as before and show their summary, but nothing is saved.
- Who you are always comes from a login session the server keeps, never from what the browser says.

Our own email-and-password accounts are not built: doing passwords safely (hashing, resets, leaks)
is a lot of security work for little gain while Google sign-in exists. Maybe later, alongside Google.

- **Home, signed in:** `playing as <display name>`; Practice, Test Yourself · 2 min, My stats,

- **My stats, guest:** "Sign in with Google to see your stats" and a **Sign in with Google** choice.
- **Leaderboard, guest:** the board as usual, with "Sign in with Google to get on the leaderboard"
  and a **Sign in with Google** choice above it.
- **Results, guest:** the usual summary plus "not saved · sign in to keep your scores". A guest test
  has no best line.
- **Display name** (after the first sign-in, before anything else): "pick a display name", a name

  **Back**.
- **Sign-in outcome messages** on Welcome/home after coming back from Google:

- Arrow keys, Enter, Esc and the mouse work as in v1.2. "Sign in with Google" is a normal menu
  button with a small G mark drawn in CSS, styled like the rest of the app (no Google script).
- Gone: the "who's playing?" screen, Switch player, remembering a player in `localStorage`.

## How sign-in works

Google's standard **authorization code flow with PKCE**, done by the server with Python's standard
library (no new dependency):

1. **Sign in with Google** opens `/auth/google`. The server makes a random `state` and a random PKCE
   `code_verifier`, stores them for 10 minutes, puts `state` in a short-lived cookie too, and
   redirects to Google's account chooser with the client id, `redirect_uri = <base url>/auth/callback`,
   `scope=openid`, `state`, `code_challenge` (SHA-256 of the verifier) and `prompt=select_account`.
2. Google sends the browser back to `/auth/callback?code=…&state=…` (or `?error=…` if cancelled).
3. The server checks the `state` in the URL equals the one in the cookie **and** is a stored,
   unexpired, unused state; it is deleted as it is used, so it works once. This stops another site
   from logging you into its account.
4. The server sends the `code` and the stored `code_verifier` with the client secret straight to
   Google's token endpoint over HTTPS and gets back an ID token. Because it came directly from
   Google over a checked TLS connection, its signature need not be verified separately (OpenID
   Connect Core §3.1.3.7), but its claims are: issuer is Google, audience is this client id, not
   expired, and a non-empty `sub`.
5. `sub` (Google's permanent id for the account) finds or creates the player. The server starts a
   session and redirects to `/`.

Only `openid` is requested: the app never receives your name, email or picture from Google.

**Sessions.** A random 32-byte token in a cookie that page scripts can't read (`HttpOnly`) and other
sites' requests don't carry (`SameSite=Lax`); on an `https` base url it is also `Secure` and uses the
`__Host-` name prefix. The database stores only the token's SHA-256, so a copied database file
can't be used to log in. Sessions last 30 days. **Sign out** deletes the session and the cookie.
Requests that change data are POST/PUT with JSON, which `SameSite=Lax` cookies are not sent with
from other sites.

**The browser never names the player.** Saving a round, My stats and changing your name all take
the player from the session. A browser can no longer save rounds as someone else.

## Settings

All from environment variables (hosting platforms take secrets this way; nothing secret is in the
repo):

| Variable | Meaning | Default |
|---|---|---|
| `MENTAL_BASE_URL` | where the app is reached; the redirect is `<this>/auth/callback` | `http://127.0.0.1:8000` |
| `MENTAL_GOOGLE_CLIENT_ID` | the Google OAuth client id | none: sign-in off |
| `MENTAL_GOOGLE_CLIENT_SECRET` | its secret | none: sign-in off |
| `MENTAL_DB` | the database file | `~/.mental/mental.db` |

Without both Google variables the app runs guest-only. `docs/google-sign-in.md` lists the Google
Cloud Console steps (project, consent screen, Web application client, the redirect addresses for
local and later the real domain) and how to set the variables.

## Storage (schema version 2)

- `players`: `id`, `google_sub` (unique, required), `name` (display name, unique ignoring case,
  empty until chosen), `created_at`.
- `sessions`: `token_hash` (SHA-256 hex of the token), `player_id`, `expires_at`.
- `oauth_states`: `state`, `code_verifier`, `expires_at`.
- `rounds` and `attempts`: as v1.2.
- **Upgrading a v1 database** (from v1.2): first a copy is saved next to it as
  `mental.db.v1-backup` (SQLite's backup API, so it is consistent), then the old tables are
  dropped and the version 2 tables created. v1.2's name players and their rounds are deleted.

## API

| Route | Who | What |
|---|---|---|
| `GET /auth/google` | anyone | redirect to Google (or to `/?signin=unavailable`) |
| `GET /auth/callback` | anyone | finish sign-in, then redirect to `/`, or `/?signin=cancelled` / `/?signin=failed` |
| `POST /auth/signout` | anyone | end the session (204) |
| `GET /api/me` | anyone | `{signed_in, name, google}`; `google` says whether sign-in is set up |
| `PUT /api/me/name {name}` | signed in | set the display name; 401 not signed in, 409 taken, 422 bad name |
| `POST /api/rounds {mode, attempts}` | anyone | `{summary, best, saved}`; saved only when signed in with a name, otherwise summary only (`best` null, `saved` false) |
| `GET /api/me/stats` | signed in | `{tests, by_category}` as v1.2; 401 otherwise |
| `GET /api/leaderboard` | anyone | `[{name, best, me}]` (`me` marks your row; ids are no longer sent) |

Removed: `GET/POST /api/players`, `GET /api/players/{id}/stats`, `player_id` in rounds.

## Not in v1.3

Deploying (domain, HTTPS, hosting); the server timing tests and keeping answers (anti-cheat for a
public leaderboard); our own email/password accounts; other sign-in providers; deleting your
account or data; rate limiting; the design overhaul (v1.4).
